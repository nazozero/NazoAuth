# PR #222：验收后排队路径修复

基线验收提交为 `2c397f58`，应用源码为 `ac266e7a`。原有 20 行短时容量结果仍只
描述其冻结配置；本文记录后续修复，不将旧通过点当作新代码的性能验证。

## 已定位的重复工作

### 审计批量落库

`AuditLedgerRepository::append_batch` 对多个事件已经只执行一条 `UNNEST` SQL，
却仍在外层执行 `BEGIN` 和 `COMMIT`。修复直接使用该语句的隐式事务：数据库
往返由 3 次变为 1 次，一批事件仍全部成功或全部回滚，幂等重复与碰撞拒绝保持不变。
验证和参数准备仍在获取连接前完成；连接保护器在结果确认前保持生效，取消或未知
结果不会将连接归还池。Required 审计的业务事务路径没有改变。

现有 `audit_ledger_append_batch_commits_atomically` 覆盖单事件、64 事件、幂等重放、
批次中途碰撞后的整体回滚及导出确认。该测试是本项修改的最小真实数据库回归。
减少往返可以缩短持有连接的时间，但不据此宣称已经消除了 mixed 2610/s 的 LWLock 突发。

## 证据边界

现有突发样本包含连接池等待 1134/1268、空闲连接为零和 63–64 个 LWLock 等待者，
足以确认服务排队，尚不能将该次突发归因到特定 SQL 或物理设备。
修复后的定向验证只需覆盖受影响路径；有效历史容量矩阵不应整套重测。
