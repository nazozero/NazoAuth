# Keycloak 每秒 12,000 次机器令牌签发复测

2026-11-24，在原三服务基准的同一台共享宿主机上，单独复测 Keycloak 26.8.2。每轮先观察 15 秒，同时满足宿主 CPU 压力 ≤0.43%、分给应用的 16 核合计忙碌 ≤1 核才算低背景压力。0.43% 取自原 NazoAuth 同档正式段的最高读数。三轮分别在第 1、5、1 个观察窗口满足条件，全部正式轮次均计入结果。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 421,749 | 11,715.25 | 0 | 87.134 / 95.623 | 15.68 / 16.26 | 1,170.4 | 0.15% / 50.45% / 2.53% |
| 2 | 425,033 | 11,806.47 | 0 | 87.119 / 97.173 | 15.66 / 16.25 | 1,176.9 | 0.09% / 42.87% / 1.49% |
| 3 | 397,793 | 11,049.81 | 0 | 115.847 / 128.033 | 15.29 / 16.00 | 1,087.0 | 0.32% / 48.08% / 2.79% |

三轮中位数为 **11,715.25 次成功签发/秒，P95 87.134 ms，P99 97.173 ms**。每轮目标 432,000 次。三轮正式段已发请求均无失败，三轮成功总量均低于目标。吞吐用成功数除以 36 秒，延迟分位数取成功响应。服务端 CPU 是应用与 PostgreSQL 的平均用核之和。

原 Keycloak 三轮中位数为 11,700.56 次/秒、P95 88.662 ms、P99 94.614 ms。限定低背景压力开测后，吞吐和延迟仍在相近水平。原 NazoAuth 同档为 12,000.03 次/秒、P95 0.926 ms、P99 1.495 ms，正式段宿主 CPU 压力为 0.16%–0.43%。

**CPU 压力的归因。** 开测前，应用绑核上的总占用分别为 0.58、0.81、0.60 核。负载期间，这 16 核上所有任务合计占用 15.70、15.69、15.61 核，Keycloak 进程自身分别使用 15.68、15.66、15.29 核。两种采样覆盖正式段约 34–35 秒，端点略有不同。第三轮另有 35.08 秒的同步 CPU 计数，16 核合计忙碌 15.60 核，同一 Docker 工作负载 cgroup 占 15.17 核，其余 cgroup 占 0.43 核。第一轮没有同步观测，第二轮只覆盖 1.00 秒。

三轮 Keycloak 均接近用满分配的 CPU。宿主 CPU 压力表示有可运行任务等待 CPU 的时间占比，覆盖整台宿主。两种服务施压期间的压力仍不同，本次无法分解共享宿主干扰和服务内部排队各自对尾延迟的贡献。

**复测条件。** 沿用原 Keycloak 镜像、专库、API 创建的机器客户端和 k6 脚本。每轮重启应用、预热 10 秒、正式测量 36 秒，960 个虚拟用户。应用限相同 16 核，PostgreSQL、发压端和采样端沿用原 CPU 分配。连接池上限为 32。三轮 PostgreSQL 配置与进程一致。通过服务接口签发并验证 RS256、2048 位 RSA、300 秒有效期和 `profile` scope，realm 成功事件存储关闭。应用、PostgreSQL 和发压端的采样线程均符合绑核配置。
